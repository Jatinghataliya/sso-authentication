Overview
A production-ready Single Sign-On application supporting three identity providers — Auth0 (OIDC), GitHub (OAuth2), and Google (OIDC). Built with Spring Boot 3.2 and Spring Security 6, it implements role-based access control, silent token refresh, single logout, and a full CI/CD pipeline deploying automatically to Railway on every push to main.

Identity Providers
Auth0
OpenID Connect
  • Full OIDC login with ID token, access token, and refresh token
  • Custom roles injected via Auth0 Actions (https://my-app.com/roles claim)
  • Silent token refresh using offline_access scope
  • Single logout via /v2/logout?client_id=...&returnTo=...
  • Callback: /login/oauth2/code/okta
GitHub
OAuth2
  • OAuth2 login with read:user and user:email scopes
  • Displays GitHub username, avatar, and profile link on dashboard
  • Token refresh skipped (GitHub tokens do not expire)
  • Local session logout only (no external logout endpoint)
  • Callback: /login/oauth2/code/github
Google
OpenID Connect
  • OIDC login with openid profile email scopes
  • Displays profile picture, full name, and email on dashboard
  • Uses Spring Boot built-in Google provider (no manual config needed)
  • Token refresh skipped (no offline_access scope)
  • Callback: /login/oauth2/code/google
Implemented Features
Implemented & live
✓ Done Multi-provider Login
Home page with three styled login buttons — Auth0, GitHub, Google. Each initiates the correct OAuth2/OIDC flow.
✓ Done Role-Based Access Control
ADMIN and USER roles extracted from Auth0 JWT claim. Pages protected with @PreAuthorize and hasRole().
✓ Done Silent Token Refresh
TokenRefreshFilter runs on every request. Proactively refreshes Auth0 access token 60s before expiry using refresh_token. GitHub and Google are skipped.
✓ Done Single Logout
Auth0 logout hits /v2/logout to clear Auth0 session. GitHub/Google do local session clear only. Session, cookies, and authentication all invalidated.
✓ Done Auth Bypass Protection
Unauthenticated access to any protected route redirects to home (/), not Spring's default /login page. Implemented via custom authenticationEntryPoint.
✓ Done Dashboard
Shows provider, profile info, assigned roles, token expiry countdown, refresh token status, and all JWT claims. Provider-specific UI (GitHub avatar, Google picture).
✓ Done Access Denied Page
Custom 403 page shown when a user lacks the required role. Displays user name and instructions to contact admin.
✓ Done REST API Endpoint
GET /api/me returns authenticated user info, provider, roles, and attributes as JSON. Useful for client-side or API integrations.
✓ Done Secrets Management
All credentials stored in environment variables. application-local.yml gitignored for local dev. No secrets in source code or Docker image.
✓ Done Docker Support
Multi-stage Dockerfile — JDK build stage + JRE runtime stage. Non-root appuser. docker-compose.yml for local dev with .env file.
✓ Done HTTPS on Railway
forward-headers-strategy: NATIVE configured so Spring Boot reads X-Forwarded-Proto from Railway's reverse proxy, generating correct https:// redirect URIs.
✓ Done CI/CD Pipeline
GitHub Actions: build + test → Docker push to GHCR → Railway deploy. Triggered on every push to main. PRs run build only.

How Role-Based Access Works
User logs in via Auth0
↓
Auth0 Action: "Add Roles to Token"
↓
ID Token claim: https://my-app.com/roles: ["admin", "user"]
↓
Auth0RolesExtractor.extractAuthorities()
↓
Spring Security: ROLE_ADMIN, ROLE_USER granted
↓
@PreAuthorize("hasRole('ADMIN')") enforced on routes
